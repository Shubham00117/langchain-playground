Tool Calling

How the LLM decides when / how to call a tool — complete mechanics

What is Tool Calling?

Tool Calling = Tool + LLM working together. The LLM decides when to call a tool, what arguments to pass, and the result is fed back to continue the conversation.

This is fundamentally different from manually calling a tool via tool.invoke(). In tool calling, the LLM is in charge — it reads the user's query and decides on its own whether a tool is needed.

Manual Tool Use

  • You explicitly call tool.invoke()
  • You decide when / how
  • No LLM involvement in routing

Tool Calling (LLM-driven)

  • LLM decides if a tool is needed
  • LLM provides the arguments
  • Result fed back to the LLM

bind_tools — Connecting Tools to LLM

llm.bind_tools([tool1, tool2]) registers the tools with the LLM. The LLM receives the tool schemas (name, description, args) and can reference them when generating a response.

The LLM does not execute tools itself. It only decides to "request" a tool call. Your code is responsible for executing the actual tool logic.

PYTHON 
from langchain_groq import ChatGroq
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

llm = ChatGroq(model="llama-3.3-70b-versatile")

# Bind the tool — LLM now "knows" about this tool
llm_with_tools = llm.bind_tools([multiply])
📋

Tool Schema

name, description, and args are sent to the LLM as part of the system context

🧠

LLM Decides

Based on the query, the LLM chooses whether to call a tool or respond directly

⚙️

You Execute

Your code reads the tool call from the response and executes it manually

Reading the Tool Call Response

When the LLM decides to call a tool, the response has response.tool_calls — a list of dicts, each containing the tool name and arguments the LLM wants to use.

The response.content will be empty when a tool call is made. You must check for tool_calls first.

PYTHON 
response = llm_with_tools.invoke("What is 3 multiplied by 5?")

# response.tool_calls is a list of dicts
print(response.tool_calls)

# Output structure:
# [{'name': 'multiply', 'args': {'a': 3, 'b': 5}, 'id': 'abc123', 'type': 'tool_call'}]

if response.tool_calls:
    for tool_call in response.tool_calls:
        print("Tool:", tool_call["name"])   # → multiply
        print("Args:", tool_call["args"])   # → {'a': 3, 'b': 5}
else:
    print(response.content)              # → direct text response

The id field in each tool call is important — you must include it when sending the tool result back in a multi-turn conversation.

The Full Tool Calling Loop

The complete tool calling workflow is a loop: User → LLM → Tool Call → Execute → Feed Result Back → LLM → Final Answer.
1

User Query

User sends a natural language query to the LLM.

2

LLM Responds with Tool Call

If a tool is needed, response.tool_calls is populated with tool name + args.

3

Execute the Tool

Your code invokes the tool with the provided arguments and captures the result.

4

Send Result Back as ToolMessage

Wrap the result in a ToolMessage and append it to the message history.

5

LLM Generates Final Answer

The LLM reads the tool result and produces the final user-facing response.

PYTHON 
from langchain_core.messages import HumanMessage, ToolMessage

messages = [HumanMessage("What is 3 multiplied by 5?")]

# Step 1: LLM decides which tool to use
ai_msg = llm_with_tools.invoke(messages)
messages.append(ai_msg)

# Step 2: Execute the tool and feed result back
for tool_call in ai_msg.tool_calls:
    result = multiply.invoke(tool_call["args"])
    messages.append(
        ToolMessage(content=str(result), tool_call_id=tool_call["id"])
    )

# Step 3: LLM generates the final answer using tool result
final_response = llm_with_tools.invoke(messages)
print(final_response.content)  # → "3 multiplied by 5 is 15."

Parallel Tool Calling

When a query requires multiple operations, the LLM can generate multiple tool calls at once in a single response. response.tool_calls will be a list with more than one item.

This is efficient because all tools can be executed in parallel, reducing latency instead of going back-and-forth for each tool one by one.

PYTHON 
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

llm_with_tools = llm.bind_tools([add, multiply])

# Query that requires BOTH tools
response = llm_with_tools.invoke("What is 3+5 and 4*7?")

# response.tool_calls has 2 items
for tc in response.tool_calls:
    print(tc["name"], tc["args"])
# → add {'a': 3, 'b': 5}
# → multiply {'a': 4, 'b': 7}

tool_choice — Forcing Tool Usage

By default, the LLM decides whether to call a tool. You can override this with tool_choice to force the LLM to always use a specific tool, or to use any tool.
PYTHON 
# Option 1: "auto" (default) — LLM decides whether to use a tool
llm.bind_tools([multiply], tool_choice="auto")

# Option 2: "any" — LLM MUST call at least one tool
llm.bind_tools([multiply], tool_choice="any")

# Option 3: force a specific tool by name
llm.bind_tools([multiply, add], tool_choice="multiply")
# → LLM will ALWAYS call multiply, regardless of the query

When to use: Use tool_choice="any" when you want to guarantee structured output (e.g., data extraction pipelines). Use a specific tool name when you need deterministic behaviour.
