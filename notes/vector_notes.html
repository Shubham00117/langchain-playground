01

Why Vector Stores?

The Problem with Keyword Search

Traditional databases use keyword matching — they search for exact words. If you search "emotional drama film", it won't find a movie described as "a heart-wrenching story about family bonds" — even though the meaning is the same.

Keyword Match vs Semantic Search

Solution: Embeddings

Text is converted into a numerical vector using a neural network (embedding model). Similar texts produce vectors that are close to each other in vector space — this enables meaning-based search.

Text → Embedding Pipeline
Key Insight: Each movie gets converted into a 512-dimensional (or higher) vector. Movies with similar plots have vectors that are close together in this high-dimensional space. Similarity is measured using cosine similarity.
Cosine Similarity — Similar Movies are Close in Vector Space
Three Capabilities a Vector Store Must Have:
C1 → Generate & store embedding vectors  |  C2 → Storage  |  C3 → Semantic search intelligence
02

What are Vector Stores?

Definition: A vector store is a system designed to store and retrieve data represented as numerical vectors.
Key Features

① Storage

Stores vectors and associated metadata. Supports two modes:

In-Memory
Fast · RAM · Temporary
On-Disk
Durable · HDD/SSD · Persistent

② Similarity Search

Retrieves vectors most similar to a query vector using distance metrics like cosine similarity or Euclidean distance. Returns top-k most relevant results.

③ Indexing

Builds special data structures for fast approximate nearest neighbor (ANN) lookups on high-dimensional vectors.

How Indexing Works: Clusters the 10 lakh vectors into groups (e.g., 10 clusters). At query time, only the relevant cluster(s) are searched — O(n) becomes much faster.

④ CRUD Operations

Full lifecycle management of vectors:

  • Create — add new vectors
  • Read — retrieve vectors
  • Update — modify existing entries
  • Delete — remove outdated vectors
Indexing via Clustering — Faster Search
Use-Cases

Semantic Search

Find documents by meaning, not just keywords. Powers intelligent Q&A systems.

RAG (Retrieval Augmented Generation)

Retrieve relevant context chunks from a knowledge base to ground LLM responses in facts.

Recommender Systems

Find items similar to what a user likes — movies, products, articles.

Image / Multimedia Search

Convert images/audio into embeddings and search by similarity across media.

Vector Store vs Vector Database

Feature Vector Store Vector Database
Definition Lightweight library/service for storing vectors & similarity search Full-fledged DB with vector + database features
Transactions Not included ACID transactions supported
Scaling Manual, separate Distributed architecture, horizontal scaling
Persistence Handle separately Built-in backup & replication
Security Minimal Auth/authorization, role-based access
Best for Prototyping, small-scale apps Production, large datasets
Examples FAISSChroma PineconeMilvusQdrantWeaviate
Summary: A vector database is effectively a vector store with extra database features (clustering, scaling, security, metadata filtering, durability). Vector DB ⊃ Vector Store.

Vector Stores in LangChain

Supported Stores

LangChain integrates with FAISS, Pinecone, Chroma, Qdrant, Weaviate, and more — giving flexibility in scale & deployment.

Common Interface

A uniform Vector Store API lets you swap backends (e.g., FAISS → Pinecone) with minimal code changes.

Metadata Handling

Attach metadata (timestamps, authors, tags) to each document — enables filter-based retrieval.

Common API Methods
LangChain Vector Store Interface Python 
# Create vector store from documents
vs = VectorStore.from_documents(docs, embedding)
# OR from raw texts
vs = VectorStore.from_texts(texts, embedding)

# Add more documents
vs.add_documents(docs)

# Similarity search — returns top k Documents
results = vs.similarity_search(query, k=4)

# Similarity search with scores
results = vs.similarity_search_with_score(query, k=4)

# Metadata filtering
results = vs.similarity_search_with_score(
    query="",
    filter={"team": "Mumbai Indians"}
)

05

Chroma Vector Store

Chroma is a lightweight, open-source vector database especially friendly for local development and small- to medium-scale production needs.
Chroma DB Hierarchy

Persistent Storage

Chroma persists data as a chroma.sqlite3 file in the specified persist_directory. Data survives session restarts — no need to re-embed documents every time.

Create Documents with Metadata

Each Document has page_content (the text) and metadata (a dict for filtering).

doc1 = Document(
    page_content="Virat Kohli is one of the most successful batsmen in IPL history...",
    metadata={"team": "Royal Challengers Bangalore"}
)
doc2 = Document(
    page_content="Rohit Sharma is the most successful captain in IPL...",
    metadata={"team": "Mumbai Indians"}
)
doc3 = Document(
    page_content="MS Dhoni, famously known as Captain Cool...",
    metadata={"team": "Chennai Super Kings"}
)
# ... more documents ...

docs = [doc1, doc2, doc3, doc4, doc5]
3

Initialize Chroma Vector Store

Create a Chroma instance with embedding function, a persistence directory (for saving to disk), and a collection name.

initialize chromaPython
vector_store = Chroma(
    embedding_function=OpenAIEmbeddings(),
    persist_directory='my_chroma_db',  # saves as SQLite file
    collection_name='sample'
)
4

Add Documents

Embed and store all documents. Returns a list of auto-generated UUIDs for each document.

View Stored Documents

Inspect what's stored — embeddings, documents, and metadata.

view all documentsPython
vector_store.get(include=['embeddings', 'documents', 'metadatas'])

6

Similarity Search

Query the vector store. Returns top-k most similar Documents.

similarity searchPython
results = vector_store.similarity_search(
    query='Who among these are a bowler?',
    k=2
)
# Returns: [Document(metadata={'team': 'Mumbai Indians'}, page_content='Jasprit Bumrah...'),
#           Document(metadata={'team': 'Chennai Super Kings'}, page_content='Ravindra Jadeja...')]
7

Similarity Search with Score

Same as above but also returns a distance score (lower = more similar in L2 distance).

similarity search with scorePython
results = vector_store.similarity_search_with_score(
    query='Who among these are a bowler?',
    k=2
)
# Returns: [(Document(...Bumrah...), 0.354),
#           (Document(...Jadeja...), 0.408)]
Note: Chroma uses L2 (Euclidean) distance by default. Lower score = more similar.
8

Metadata Filtering

Filter results to a specific metadata value before running similarity search.

metadata filterPython 
results = vector_store.similarity_search_with_score(
    query="",
    filter={"team": "Chennai Super Kings"}
)
# Only returns documents where team == "Chennai Super Kings"
# Result: MS Dhoni (0.648), Ravindra Jadeja (0.656)
9

Update Documents

Update a document by its UUID (obtained when adding documents).

update documentPython 
updated_doc1 = Document(
    page_content="Virat Kohli, the former captain of RCB, is renowned...",
    metadata={"team": "Royal Challengers Bangalore"}
)
vector_store.update_document(
    document_id='fdb1dc2c-b27b-4f18-80ef-ee48f4d9a31f',
    document=updated_doc1
)
10

Delete Documents

Remove a document by its UUID. Pass IDs as a list.

delete documentPython 
vector_store.delete(ids=['fdb1dc2c-b27b-4f18-80ef-ee48f4d9a31f'])

# Verify deletion
vector_store.get(include=['embeddings', 'documents', 'metadatas'])
# The deleted document will no longer appear in results
